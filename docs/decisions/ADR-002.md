# ADR-002 — Mandatory Per-Turn Model Preset and Fresh Context Injection

## Status
Accepted

## Date
2026-09-27

## Context
The repository now contains durable project memory and recovery records. However, a memory repository alone does not guarantee that the model actually receives the operating rules and current project state on each turn.

A model can have access to durable memory but still behave inconsistently if the required instructions are only supplied once per session or if a previous dynamic context snapshot becomes stale.

## Decision
Every model invocation in Popularity-Generator will use a three-part context contract:

1. Mandatory static model preset.
2. Fresh project-context snapshot rebuilt from authoritative repository records.
3. Current user/task input.

The preset and the per-turn context contract will be stored in the repository and treated as implementation requirements for the future model runtime.

## Consequences
### Positive
- Operating rules survive session/model changes.
- Every turn starts from explicit project instructions.
- Dynamic project state is refreshed instead of being trusted from a prior turn.
- Memory recovery becomes a repeatable runtime operation.

### Trade-offs
- Every turn incurs context construction and token cost.
- The runtime must maintain a reliable context-builder/middleware layer.
- Repository state must remain internally coherent for the injected context to be trustworthy.

## Rejected Approach
Injecting the preset only once at session initialization is insufficient because it does not satisfy the per-turn continuity requirement.
