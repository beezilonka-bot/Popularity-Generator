# ADR-003 — Keyword-Routed World Book for Adaptive Context

- Status: Accepted
- Date: 2026-09-27

## Context

The project needs more than a static skill library. Loading every skill, style rule, resource, and research note on every model turn wastes context and makes the model less focused.

SillyTavern World Info demonstrates a useful pattern: entries have activation keys and are inserted into the prompt only when relevant. Its documented design also includes filters, insertion priority, context budgeting, and bounded recursive activation. citeturn0search0

Open-source extensions such as DeepLore demonstrate a second useful pattern for scale: use cheap keyword/fuzzy retrieval as a first pass and a more expensive semantic/AI selection step only for candidates that need it. citeturn0search5turn0search9

## Decision

Adopt a project-owned World Book layer with:

1. exact keyword and alias matching as the default fast path;
2. optional regex for cases where plain keywords are insufficient;
3. optional AND/ANY/NOT filters;
4. deterministic priority and token-budget selection;
5. bounded recursive activation;
6. resource references and source traceability;
7. semantic retrieval as an optional later fallback, not a required dependency;
8. minimal injection into the existing per-turn context contract.

## Why

This keeps the hot path small and predictable while allowing the knowledge/skill library to grow without forcing the entire library into every prompt.

The World Book is a retrieval mechanism, not a second source of truth. Authoritative project state remains in the existing project-state files.

## Rejected

- Injecting the complete skill library on every turn.
- Making embeddings/vector search mandatory before keyword routing works.
- Copying large external repositories into prompts.
- Using random activation for ordinary skills or constraints.
- Letting World Book entries override project state or hard constraints.

## Consequences

Positive:
- Lower context usage.
- Faster routing for common tasks.
- Skills/resources can scale independently of the model preset.
- Activation can be inspected and debugged.

Costs:
- Requires a registry and resolver.
- Poor keywords can cause missed activations.
- Recursive or semantic retrieval can add complexity and latency.

## Source Notes

External systems are treated as design research. Their mechanisms are adapted to this project's needs rather than copied as implementation text.
