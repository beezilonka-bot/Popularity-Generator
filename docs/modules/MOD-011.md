# MOD-011 — World Book Retrieval & Context Injection

## Purpose

Provide a lightweight World Book mechanism inspired by SillyTavern World Info/Lorebook behavior: when the current task contains relevant trigger terms or patterns, automatically select the smallest useful set of project-owned context, skills, resources, and style guidance and add them to the model context.

## Scope

MOD-011 owns:
- world-book entry schema;
- keyword/alias/regex trigger matching;
- optional AND/ANY/NOT filters;
- priority and token-budget selection;
- deduplication;
- bounded recursive activation;
- resource references;
- routing activated entries into the per-turn context package.

It does not own:
- the underlying model;
- web search itself;
- long-term project state;
- the content-generation engine;
- bulk copying of external text.

## Entry Types

A World Book entry may provide:
- `skill` — reusable operating method;
- `context` — project/domain facts or constraints;
- `style` — writing-style guidance;
- `resource` — links, repositories, documentation, examples, or research notes;
- `example` — short project-owned examples;
- `constraint` — hard rules or exclusions.

## Retrieval Contract

For each model turn:

1. Read the current task and other allowed scan text.
2. Normalize the text without destroying meaningful case or punctuation.
3. Match exact keywords/aliases first; support regex only where justified.
4. Apply optional filters.
5. Rank activated entries by specificity, priority, and trigger strength.
6. Deduplicate by permanent entry ID.
7. Follow references/recursive triggers only within a bounded depth.
8. Stop when the World Book token budget is reached.
9. Inject only the selected entries into the per-turn package.
10. Record enough trace information to explain why an entry was activated.

## Design Principles

- Retrieval is selective, not "load the whole knowledge base".
- A keyword is a trigger, not evidence that every related entry is needed.
- Every entry must be standalone because only activated content is injected.
- Prefer exact/alias matching before expensive retrieval.
- Use semantic retrieval only as a later fallback for cases keyword matching misses.
- Higher priority does not override hard constraints or budget limits.
- Duplicate or near-duplicate entries should be merged or retired.
- External material is research input; store operationalized rules and links rather than bulk copied text.
- Unknown facts remain unknown.
- The World Book may support a model, but it never guarantees that the model will use an injected entry.

## Acceptance Criteria

- A relevant keyword activates the intended entry.
- Irrelevant tasks do not load unrelated entries.
- Multiple matches are deduplicated and budgeted.
- AND/ANY/NOT filters behave deterministically.
- Recursive activation is bounded.
- Each activated entry has a traceable ID and source.
- The per-turn package contains only the resolved World Book subset.
- The system can operate without semantic retrieval.
