# MOD-010 — Model Operating Preset & Per-Turn Context Injection

## Identity
- ID: MOD-010
- Stage: STAGE-001
- Introduced: v0.1.1
- Status: active

## Purpose
Define the mandatory operating instructions that are injected into every model turn, together with the current project context needed for that turn.

This module separates:
1. **Preset** — stable instructions about how the model must work.
2. **Recovery context** — current authoritative project state loaded from the repository.
3. **Task context** — the user's current request and task-specific material.

## Mandatory Per-Turn Contract
Every model invocation in this project MUST receive, in this order:

1. `MODEL_PRESET.md`
2. A fresh context snapshot derived from `PROJECT_STATE.md`, `REGISTRY.yaml`, and the active task's relevant records.
3. The current user/task input.

The preset MUST NOT be injected only at session start. It is a per-turn requirement.

## Operating Rules
- Treat repository state as the durable source of project memory.
- Recover before acting when context is missing, truncated, or uncertain.
- Never invent undocumented project history, decisions, status, IDs, or completed work.
- Distinguish current state from historical logs.
- Use permanent IDs when referring to stages, modules, loops, releases, and ADRs.
- Before changing project architecture, consult relevant ADRs and current state.
- After material changes, update the affected state/index/history records.
- Keep the active task scoped to the current stage unless the task explicitly changes stage.
- When a required fact is unavailable, state that it is unknown rather than guessing.
- The user's current instruction has priority for the immediate task, but cannot silently invalidate repository source-of-truth records.

## Memory Recovery Behavior
If the conversation is truncated or starts without reliable prior context:
1. Read `AI_CONTEXT.md`.
2. Read `PROJECT_STATE.md`.
3. Read `REGISTRY.yaml`.
4. Read the active stage and loop.
5. Read only the module/release/ADR records relevant to the current task.
6. Reconstruct the working state from those records.
7. Continue from the documented next action; do not recreate or rewrite history merely because chat history is missing.

## Context Freshness
The dynamic recovery snapshot MUST be generated or refreshed for every turn. A previous turn's snapshot is not considered authoritative for the next turn.

## Non-Goals
- This module does not itself implement model API calls.
- This module does not store secrets.
- This module does not replace the repository memory records.

## Acceptance Criteria
- A model turn always has the preset.
- A model turn always has a fresh project-context snapshot.
- A new session can recover the same documented state without relying on chat history.
- Missing information is represented as unknown rather than inferred.
- The injection contract is explicit enough to be implemented by future runtime middleware.
